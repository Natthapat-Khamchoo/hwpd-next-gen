## 1. ต้องทำก่อนใช้งานจริง (Blocking)

เรียงตามลำดับที่ควรทำ

### 1.1 รัน `scripts/sync_sheet_headers.py` กับชีตจริง

รอบนี้เพิ่ม **5 ตารางใหม่** และ **7 คอลัมน์** ในตารางเดิม ชีตของหน่วยยังไม่มี

```bash
cd python_backend
python scripts/sync_sheet_headers.py --dry-run   # ดูก่อน
python scripts/sync_sheet_headers.py             # เขียนจริง
```

ตารางใหม่: `tb_AuditLog`, `tb_OverweightTrucks`, `tb_PR_News`, `tb_PR_Media`,
`tb_PR_Keywords`
คอลัมน์ใหม่: พิกัดใน `tb_Checkpoints`, slip ใน `tb_FuelOil`, ว.20 สองช่องใน
`tb_DailyResult`, ว.4 ใน `tb_DailyReport`, flag archive ใน `tb_National_Summary`

สคริปต์ปฏิเสธที่จะทำงานถ้าหัวตารางในชีตไม่ใช่คำนำหน้าของ schema ซึ่งแปลว่ามีคน
แทรกคอลัมน์เอง กรณีนั้นต้องให้คนดูก่อน

### 1.2 ให้ Spreadsheet ID ของ กก.8

`config.py` มี ID จริงแค่ กก.1 กับ กก.5 **ข้อ 3 สั่งให้ Dashboard นับเฉพาะ กก.8
แต่ กก.8 ยังไม่มีฐานข้อมูล** โค้ดพร้อมแล้ว ทดสอบตัวเลขจริงไม่ได้

ถ้ายังไม่มี ให้สร้างด้วย `python scripts/setup_database.py --divisions 8`

### 1.3 ตรวจ 3 เรื่องที่ต้องใช้ความรู้เฉพาะทาง

| เรื่อง | ใครตรวจ | แก้ที่ไหน |
|---|---|---|
| พิกัดน้ำหนักตามจำนวนเพลา (ข้อ 8) | ฝ่ายกฎหมาย | `report_service.LEGAL_WEIGHT_BY_AXLE` + `OverweightForm.tsx` |
| การจัดกลุ่มข้อหาเข้า 4 พ.ร.บ. (ข้อ 14) | ฝ่ายกฎหมาย | คอลัมน์ F ของ `tb_Charges` |
| นิยาม "หัวหน้าหน่วยงาน" (ข้อ 2) | ฝ่ายกำลังพล | `user_service.HEAD_ROLES` |

ทั้งสามเรื่องระบบมีค่าเริ่มต้นที่ใช้งานได้อยู่แล้ว แต่**ไม่ใช่คำตอบที่ถูกต้องตามกฎหมาย
หรือระเบียบ** ข้อหาที่ระบบเดากลุ่มไม่ได้ตกไปอยู่ "ข้อหาเฉพาะทาง" ซึ่งปลอดภัยกว่า
เดาผิดกลุ่ม

### 1.4 ทดสอบบนเครือข่ายจริงของหน่วย

- แผนที่ต้องต่อออก `tile.openstreetmap.org` ถ้าถูกบล็อกจะขึ้นพื้นเทา
  (ยังปักหมุดได้ เพราะพิกัดคำนวณจากตำแหน่งคลิก)
- ปุ่ม Copy Text ใช้ `navigator.clipboard` ซึ่งต้องเป็น https

## 2. โมดูล PR ส่วนที่เหลือ (ข้อ 13)

**FR-07/08 และ FR-10 ทำแล้ว** (5 ส.ค. 2569) เหลือสาม FR ที่ยังติดของนอกโค้ด

| FR | เรื่อง | ติดอะไร | ประมาณการ |
|---|---|---|---|
| FR-03 | ตั้งเวลาเผยแพร่ + เก็บ Post ID/Permalink | ต้องมี Facebook App ที่ผ่าน App Review + Page Access Token ซึ่งรออนุมัติเป็นสัปดาห์ | 1 วัน หลังได้ token |
| FR-06 | AI เกลาข้อความ + Diff View | ต้องมี API key และงบประมาณ | 1 วัน |
| FR-01 (ส่วนที่เหลือ) | รับข่าวจาก CIB / HWPD API | ยังไม่มีสเปก API ปลายทาง | รอสเปก |

**คอลัมน์รอไว้แล้ว** `Post_ID`, `Permalink`, `วันเวลาที่เผยแพร่` ใน `tb_PR_News`
และ `เนื้อหาที่เรียบเรียงแล้ว` สำหรับ FR-06 จึงไม่ต้องแก้ schema อีกรอบ
`compose()` ของ FR-07 หยิบช่อง `เนื้อหาที่เรียบเรียงแล้ว` ไปใช้เองอยู่แล้วเมื่อมีค่า
พอทำ FR-06 เสร็จชิ้นงาน PR จะใช้ข้อความที่เกลาแล้วทันทีโดยไม่ต้องแก้เทมเพลตอีกรอบ

### สิ่งที่ FR-07/08 ทำไปแล้ว

- เทมเพลตสามแบบ — ข่าวแจกสื่อมวลชน / โพสต์เพจ / ข้อความกลุ่มไลน์
- ปุ่ม "ประกอบชิ้นงาน" ให้อ่านก่อน แยกจากปุ่ม "สร้างลิงก์" ที่แตะ Drive จริง
- ลิงก์สาธารณะสร้างได้เฉพาะข่าวที่ **อนุมัติแล้ว** และเฉพาะแอดมิน
- สิทธิ์ที่ให้คือ `anyone / reader` **ให้ที่ตัวไฟล์ชิ้นงานเท่านั้น ไม่ใช่ที่โฟลเดอร์ไฟล์แนบ**
- มีปุ่มถอนลิงก์ในหน้าเดียวกัน ตัวไฟล์ไม่ถูกลบ เพื่อให้ตามย้อนได้ว่าเคยแจกอะไร
- สร้างลิงก์ใหม่ทับของเดิมจะถอนลิงก์เก่าให้อัตโนมัติ
- ทุกครั้งเขียน `tb_AuditLog` (PUBLISH ตอนสร้าง / UPDATE ตอนถอน)

คอลัมน์ใหม่ใน `tb_PR_News`: `เทมเพลตชิ้นงาน PR`, `Share_File_ID`, `Share_Url`,
`วันเวลาที่สร้างลิงก์` — **ต้องรัน `sync_sheet_headers.py` ก่อนใช้งานจริง** (ข้อ 1.1)

## 4. หนี้ทางเทคนิคที่ค้างมาก่อนรอบนี้

ไม่ได้เกิดจากงาน 16 ข้อ แต่จะโตขึ้นเรื่อย ๆ ถ้าไม่จัดการ

### 4.1 ไฟล์ Drive 20 รายการยังเปิดให้ทุกคนที่มีลิงก์แก้ไขได้

รวมถึงแท็บที่เก็บชื่อจริงและเบอร์โทรเจ้าหน้าที่ (บันทึกไว้ใน
`docs/แผนย้ายไปฐานข้อมูลจริง.md` หัวข้อ 8) **เรื่องนี้ควรทำก่อน FR-07/08**
ที่จะสร้างลิงก์แชร์สาธารณะเพิ่ม

### 4.2 ระบบผูกกับบัญชี Google บัญชีเดียว

องค์กรบล็อกการสร้าง service account key ระบบจึงใช้ OAuth ของบัญชีเดียวทั้งระบบ
ถ้า token โดนเพิกถอน **ระบบดับทั้งระบบ** และเป็นต้นเหตุของเพดาน 60 คำขอ/นาที

### 4.3 โควตา Google Sheets

รอบนี้เพิ่มการเขียนจาก audit log และโมดูล PR ผมลดผลกระทบด้วยการทำ buffer
(หนึ่ง request = หนึ่งคำขอ) และให้แผนที่อ่านเฉพาะชั้นที่เปิด แต่เพดานยังอยู่
**ถ้าเริ่มเจอ 429 บ่อย คือสัญญาณว่าถึงเวลาย้ายฐานข้อมูลจริง** ตามแผนใน
`docs/แผนย้ายไปฐานข้อมูลจริง.md`

### 4.4 `tb_National_Summary` เคยเต็ม 1,023 แถวจนข้อมูลหาย 6 กก. แบบเงียบ

ข้อ 3 ที่เก็บ กก.1-7 ไว้เป็น archive ทำให้แถวโตเร็วขึ้น **ควรเช็คเพดานแถว
ก่อนเปิดใช้จริง**

### 4.5 ยังมีบัญชี `(รอระบุชื่อ)` 43 บัญชี และข้อมูลทดสอบปนอยู่

ควรล้างก่อน UAT ไม่งั้นตัวเลขในรายงานจะไม่ตรงกับความจริง
