## 2. โมดูล PR ส่วนที่เหลือ (ข้อ 13)

**FR-07/08 และ FR-10 ทำแล้ว** (5 ส.ค. 2569) เหลือสาม FR ที่ยังติดของนอกโค้ด

| FR | เรื่อง | ติดอะไร | ประมาณการ |
|---|---|---|---|
| FR-03 | ตั้งเวลาเผยแพร่ + เก็บ Post ID/Permalink | ต้องมี Facebook App ที่ผ่าน App Review + Page Access Token ซึ่งรออนุมัติเป็นสัปดาห์ | 1 วัน หลังได้ token |

**คอลัมน์รอไว้แล้ว** `Post_ID`, `Permalink`, `วันเวลาที่เผยแพร่` ใน `tb_PR_News`

### บัญชีฝ่ายประชาสัมพันธ์ (`PR_Officer`)

เพิ่มตามที่หน่วยขอ — บัญชีระดับ บก. สถานี `"00"` ที่ทำงาน PR ได้เต็มวงจรทุก กก.
แต่แตะอย่างอื่นในระบบไม่ได้เลย หน้าแรกคือ `PrCenterDashboard` ซึ่งมีตัวเลือก กก.

ข้อจำกัดบังคับที่ backend ด้วย allowlist (`PR_ONLY_ALLOWED_PREFIXES`) ไม่ใช่แค่ซ่อนเมนู
เพราะสถานี `"00"` ผ่านด่านขอบเขตสถานีได้ทุกกองอยู่แล้ว

**ต้องสร้างบัญชีจริงก่อนใช้งาน** — `python scripts/create_station_users.py --apply`
จะสร้าง `pr0` ให้ (รหัสผ่านสุ่ม อยู่ในไฟล์ CSV ที่สคริปต์เขียนออกมา) ถ้าหน่วยต้องการ
ฝ่าย PR มากกว่าหนึ่งคน ให้เพิ่มแถวใน `tb_Users` โดยตั้ง Role เป็น `PR_Officer`
และ Station_ID เป็น `00`

### สิ่งที่ FR-07/08 ทำไปแล้ว

- เทมเพลตสามแบบ — ข่าวแจกสื่อมวลชน / โพสต์เพจ / ข้อความกลุ่มไลน์
- ปุ่ม "ประกอบชิ้นงาน" ให้อ่านก่อน แยกจากปุ่ม "สร้างลิงก์" ที่แตะ Drive จริง
- ลิงก์สาธารณะสร้างได้เฉพาะข่าวที่ **อนุมัติแล้ว** และเฉพาะแอดมิน
- สิทธิ์ที่ให้คือ `anyone / reader` **ให้ที่ตัวไฟล์ชิ้นงานเท่านั้น ไม่ใช่ที่โฟลเดอร์ไฟล์แนบ**
- มีปุ่มถอนลิงก์ในหน้าเดียวกัน ตัวไฟล์ไม่ถูกลบ เพื่อให้ตามย้อนได้ว่าเคยแจกอะไร
- สร้างลิงก์ใหม่ทับของเดิมจะถอนลิงก์เก่าให้อัตโนมัติ
- ทุกครั้งเขียน `tb_AuditLog` (PUBLISH ตอนสร้าง / UPDATE ตอนถอน)

คอลัมน์ใหม่ใน `tb_PR_News`: `เทมเพลตชิ้นงาน PR`, `Share_File_ID`, `Share_Url`,
`วันเวลาที่สร้างลิงก์` — **ต้องรัน `sync_sheet_headers.py` ก่อนใช้งานจริง** (ข้อ 1.1)

## 4. หนี้ทางเทคนิคที่ค้างมาก่อนรอบนี้

ไม่ได้เกิดจากงาน 16 ข้อ แต่จะโตขึ้นเรื่อย ๆ ถ้าไม่จัดการ

### 4.1 ~~ไฟล์ Drive เปิดให้ทุกคนที่มีลิงก์แก้ไขได้~~ — ปิดแล้ว 5 ส.ค. 2569

ของจริงกว้างกว่าที่เอกสารเดิมบันทึก — **สเปรดชีตปฏิบัติการทั้ง 8 กอง ชีตกลาง และ
โฟลเดอร์ไฟล์แนบทั้ง 8 กอง รวม 17 รายการ** ตั้งเป็น `anyone / writer` ทั้งหมด

ผลที่หนักที่สุดไม่ใช่ข้อมูลรั่ว แต่คือ **ข้ามระบบล็อกอินได้ทั้งระบบ** ชีตกลางเก็บ
`tb_Users` ซึ่งมีคอลัมน์ `Password` กับ `Role` และ `verify_password` ยังรองรับรหัสผ่าน
plaintext ไว้สำหรับบัญชีเก่า คนที่มีลิงก์จึงพิมพ์รหัสผ่านลงช่อง Password ของบัญชีใดก็ได้
เปลี่ยน Role เป็น `Super_Commander` แล้วล็อกอินเข้ามาเป็นคนนั้นได้ทันที

ปิดด้วย `python scripts/lock_drive_sharing.py --apply` ตรวจซ้ำแล้วขึ้น "ปิดอยู่แล้ว"
ครบ 17 รายการ และยืนยันว่าระบบยังอ่านเขียนชีตได้ปกติ

**บทเรียนตอนแก้** Drive ไม่ยอมให้ลบ permission ที่สืบทอดมาจากโฟลเดอร์แม่ (403
cannotDeletePermission) รอบแรกไล่ลบทีละไฟล์แล้วล้มครบทั้ง 17 อัน ทุกอย่างสืบทอดจาก
โฟลเดอร์เดียวชื่อ `ตัวเทส ระดับ บก.` ปิดที่นั่นที่เดียวจบทั้งสาย สคริปต์ตอนนี้ไล่หา
ต้นทางให้เอง

**ยังต้องตรวจซ้ำเป็นระยะ** โดยเฉพาะหลังมีคนสร้างชีตหรือโฟลเดอร์ใหม่ รันสคริปต์โดย
ไม่ใส่ `--apply` ได้ตลอด ไม่แก้อะไร

### 4.2 ระบบผูกกับบัญชี Google บัญชีเดียว

องค์กรบล็อกการสร้าง service account key ระบบจึงใช้ OAuth ของบัญชีเดียวทั้งระบบ
ถ้า token โดนเพิกถอน **ระบบดับทั้งระบบ** และเป็นต้นเหตุของเพดาน 60 คำขอ/นาที

### 4.3 โควตา Google Sheets

รอบนี้เพิ่มการเขียนจาก audit log และโมดูล PR ผมลดผลกระทบด้วยการทำ buffer
(หนึ่ง request = หนึ่งคำขอ) และให้แผนที่อ่านเฉพาะชั้นที่เปิด แต่เพดานยังอยู่
**ถ้าเริ่มเจอ 429 บ่อย คือสัญญาณว่าถึงเวลาย้ายฐานข้อมูลจริง** ตามแผนใน
`docs/แผนย้ายไปฐานข้อมูลจริง.md`
