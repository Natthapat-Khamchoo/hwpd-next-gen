### บั๊กที่เจอรอบนี้ (4 จุด แก้แล้วทั้งหมด)

1. **`GET /api/health/database` ตอบ 500 เมื่อเปิดสเปรดชีตไม่ได้** — gspread โยน
   `SpreadsheetNotFound` ที่ไม่ได้สืบทอด error ของโปรเจกต์ จึงหลุด `except` ไป
   หน้าผู้บังคับการเลยค้าง "กำลังตรวจสอบ" ตลอดไป ทั้งที่ endpoint นี้มีไว้บอกว่า
   กองไหนพัง แก้แล้วเห็นสถานะรายกองครบ 8 กองทันที มีเทสคุมใน `test_database_health.py`

2. **`GET /api/health/database` ไม่มีการจำกัดสิทธิ์** — มีแค่ `current_session`
   ผู้ปฏิบัติทุกคนจึงอ่านรหัสสเปรดชีตของทุกกองกับอีเมลบัญชีบริการได้ เพิ่ม `_require_hq()`
   ตามหน้าที่เรียกใช้จริง (หน้าผู้บังคับการเท่านั้น) เจอจากการเขียนเทสสิทธิ์คู่กับข้อ 1

3. **ตารางประวัติการส่งอ่านไม่ออกทั้งใบ** — พื้นขาวทึบกับตัวหนังสือขาว ต้นเหตุคือ
   `<style>` ที่ Apps Script scope ไว้ที่ `#formMyHistory` ไม่ได้ถูกย้ายมาตอนพอร์ต
   Bootstrap จึงใส่พื้นขาวเป็นค่าเริ่มต้น ยกกฎเดิมมาเป็นคลาส `.table-history`
   ตารางอื่นทั้ง 26 จุดในระบบใช้ `table-sc`/`table-hq` อยู่แล้ว ใบนี้เป็นใบเดียวที่หลุด

4. **ช่องวันที่ภาษาไทยค้างค่าเดิม** เมื่อฟอร์มเปลี่ยนค่าจากข้างนอก (ปุ่ม "เวลาปัจจุบัน"
   หรือร่างที่กู้คืน) — โค้ดเทียบ `value !== fp.input.value` แต่ input ตัวนั้นเป็นของ React
   ซึ่งเขียนค่าใหม่ลงไปตั้งแต่ตอน commit ที่เกิดก่อน effect เสมอ ค่าจึงเท่ากันทุกครั้ง
   `setDate` เลยไม่เคยถูกเรียก ผลคือช่อง ISO เปลี่ยนตามแต่ช่องที่เจ้าหน้าที่มองเห็น
   ค้างวันเดิม — เห็นวันผิดโดยไม่รู้ตัว แก้โดยจำค่าที่ push เข้า flatpickr เอง

ข้อ 3 กับ 4 ไม่มีเครื่องมือไหนจับได้นอกจากเปิดหน้าจริง `tsc`, `lint`, `build` ผ่านหมด

## 5 ส.ค. 2569 — ตรวจกับ Google จริงก่อนส่งมอบ

รอบก่อนหน้าทุกอย่างรันบนชั้นจำลอง รอบนี้ยิงกับสเปรดชีตและ Drive ของจริง

### ช่องโหว่ที่เจอ — ข้ามระบบล็อกอินได้ทั้งระบบ

เอกสารเดิมบันทึกว่า "ไฟล์ 20 รายการแชร์แบบแก้ไขได้" ตรวจของจริงพบว่าเป็น
**สเปรดชีตปฏิบัติการทั้ง 8 กอง + ชีตกลาง + โฟลเดอร์ไฟล์แนบ 8 กอง รวม 17 รายการ**
ตั้งเป็น `anyone / writer` ทุกอัน

ที่หนักกว่าข้อมูลรั่วคือ ชีตกลางเก็บ `tb_Users` ซึ่งมีคอลัมน์ `Password` กับ `Role`
และ `verify_password` ยังรองรับรหัสผ่าน plaintext ไว้สำหรับบัญชีเก่า **คนที่มีลิงก์
พิมพ์รหัสผ่านลงช่อง Password ของบัญชีใดก็ได้ เปลี่ยน Role เป็น `Super_Commander`
แล้วล็อกอินเข้ามาเป็นคนนั้นได้ทันที** ไม่ต้องเจาะอะไรเลย

ปิดครบ 17 รายการแล้ว ตรวจซ้ำขึ้น "ปิดอยู่แล้ว" ทุกอัน ระบบยังอ่านชีตได้ปกติ
(tb_Users 110 บัญชี, กก.1 และ กก.5 อ่านได้)

รอบแรกที่แก้ล้มครบทั้ง 17 อัน เพราะ Drive ไม่ยอมให้ลบ permission ที่สืบทอดมาจาก
โฟลเดอร์แม่ ไล่ขึ้นไปพบว่าทุกอย่างสืบทอดจากโฟลเดอร์เดียว ปิดที่นั่นที่เดียวจบทั้งสาย

### FR-08 ทำงานได้จริงกับ Drive

ทดสอบครบวงจรแล้วลบไฟล์ทดสอบทิ้ง

| ขั้น | ผล |
|---|---|
| อัปไฟล์ + ตั้ง `anyone/reader` | สำเร็จ |
| สิทธิ์ที่ติดจริงบนไฟล์ | `anyone/reader` เท่านั้น ไม่มี writer |
| **เปิดลิงก์แบบไม่ล็อกอินเลย** | **HTTP 200 ได้เนื้อหาจริง** |
| ถอนลิงก์ | สำเร็จ |

ข้อสามคือหลักฐานว่าคนนอกเปิดได้จริง ไม่ใช่แค่ API ตอบว่าสำเร็จ และการปิดโฟลเดอร์แม่
ไม่กระทบการแชร์รายไฟล์

### หัวตารางกับแท็บใหม่

ซิงก์ครบ 9 สเปรดชีต รันซ้ำขึ้น "แก้ 0 แท็บ ติดปัญหา 0 แท็บ" ทุกกอง

4 แท็บของ กก.1 ที่หัวไม่ตรง ดึงข้อมูลจริงมาดูก่อนตัดสินใจ พบว่าตรงกับความหมายของ
schema ทุกจุด ผิดแค่ป้ายชื่อ ไม่มีคอลัมน์เลื่อน — ป้าย "รถวิทยุตรวจเขต" เก็บชื่อพลขับ
"Structured_Items" เก็บขอบเขตหมาย จึงเขียนทับแล้ว ซึ่งแก้ป้ายที่ผิดให้ถูกด้วย

สร้างแท็บใหม่ล่วงหน้าให้ครบทุกกองแล้ว ผู้ทดสอบจะได้ไม่เจอ edge case ของการเขียนครั้งแรก
