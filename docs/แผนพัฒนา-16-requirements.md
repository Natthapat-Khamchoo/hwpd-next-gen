## 1. ข้อสรุปที่ต้องอ่านก่อน

**งานทั้ง 16 ข้อรวมกันประมาณ 13-14 วัน ไม่ใช่ 7 วัน**

แยกเป็น EPIC 1-3 (13 requirement) ประมาณ 8 วัน และ EPIC 4 โมดูลประชาสัมพันธ์
(1 requirement แต่มี 10 FR) อีก 5-6 วัน

โมดูล PR ตอนนี้เป็นไฟล์ placeholder 12 บรรทัด (`react_frontend/src/components/forms/PrForm.tsx`)
ยังไม่มีตาราง ไม่มี endpoint ไม่มีอะไรเลยนอกจากปุ่มในเมนู งานข้อ 13 ข้อเดียว
หนักกว่า 15 ข้อที่เหลือรวมกันเกือบเท่าตัว

แผนในเอกสารนี้จึงเสนอ **ทำ EPIC 1-3 ให้ครบใช้งานได้จริง + PR module เฉพาะแกนหลัก
(FR-01, 02, 04, 05, 09)** ภายใน 7 วัน ส่วน FR-03 เผยแพร่อัตโนมัติ, FR-06 AI เกลาข้อความ,
FR-07/08 สร้างลิงก์แชร์, FR-10 รายงานสรุป ย้ายไปรอบสอง

## 2. สถาปัตยกรรมที่มีอยู่ (ผลการสำรวจ)

| ชั้น | ของที่ใช้จริง | ผลต่อแผน |
|---|---|---|
| ฐานข้อมูล | Google Sheets 13 ตาราง แยกไฟล์ตาม กก. ผ่าน `DB_ROUTER` | ไม่มี SQL ตามที่ requirement แนะนำ |
| Backend | FastAPI 61 endpoint ใน `main.py` 1,627 บรรทัด + 16 service | โครงพร้อม เพิ่ม endpoint ได้เลย |
| Frontend | React 19 + Vite + Bootstrap 5 + Tailwind v4 + ApexCharts | **ไม่มี react-router** สลับหน้าด้วย state ใน `App.tsx` |
| ไฟล์แนบ | Google Drive ผ่าน base64 ใน JSON body จำกัด 10 ไฟล์ / 10 MB ต่อไฟล์ | **ชนเพดานแน่ถ้าอัปวิดีโอ 1080p** |
| สิทธิ์ | HMAC session token 7 role ตรวจที่ endpoint | ต้องแยก read/write scope เพิ่ม |
| เทส | pytest 24 ไฟล์ stub ที่ `read_table` | เพิ่มเทสตามของเดิมได้ |

### ของที่มีอยู่แล้วและใช้ต่อได้ทันที

- `tb_Arrests` และ `tb_Accidents` มีคอลัมน์ ละติจูด/ลองจิจูด แล้ว ฟอร์มก็เก็บแล้ว
  ผ่านปุ่ม `navigator.geolocation` ทำแผนที่ได้เลยโดยไม่ต้องแก้ schema
- Soft delete มีอยู่แล้วทุกตาราง (`Sys_Status` + `Sys_IsActive`) requirement ข้อ FR-05
  ที่ขอ soft delete จึงตรงกับของเดิม ไม่ต้องออกแบบใหม่
- `query_service.set_status` ใช้ยกเลิกรายการได้แล้ว ข้อ 10 ขาดแค่ฝั่งแก้ไข
- `report_cache_service` และ `national_service` รวมยอดข้ามหน่วยได้แล้ว ข้อ 1 กับ 3
  ต่อยอดจากตรงนี้

### ของที่ไม่มีและต้องสร้างใหม่

- `tb_Checkpoints` **ไม่มีคอลัมน์พิกัด** (ข้อ 16 ต้องแก้ schema)
- `tb_FuelOil` **ไม่มีคอลัมน์ slip** (ข้อ 7)
- ไม่มีตาราง audit log และไม่มีตารางใด ๆ ของโมดูล PR
- ไม่มี leaflet ใน package.json
- `tb_Charges` เก็บชื่อข้อหาเป็นข้อความเปล่า **ไม่มีคอลัมน์กลุ่ม พ.ร.บ.** (ข้อ 14)

### ของที่ requirement ขอ แต่มีอยู่แล้วบางส่วน

**ข้อ 11 (ว.4 หลายนาย)**: `DailyReportForm.tsx` แท็บ 5 "ว.4 อื่นๆ" มี repeater เพิ่มเจ้าหน้าที่
อยู่แล้ว (บรรทัด 433-439) แต่แท็บ 1 รายงานประจำวันยังล็อกไว้ 3 ตำแหน่งตายตัว
(ผู้ปฏิบัติหน้าที่ประจำหน่วย / พลขับ / พนักงานวิทยุ) ตามคอลัมน์ใน `tb_DailyReport`
งานจริงคือยกแบบจากแท็บ 5 มาใส่แท็บ 1 แล้วเพิ่มช่องตำแหน่ง/บทบาทที่แท็บ 5 ยังไม่มี

## 3. เรื่องที่ติดและต้องการคำตอบจากคุณ

เรียงตามความเร่งด่วน สี่ข้อแรกบล็อกงานจริง

### 3.1 กก.2, 3, 4, 6, 7, 8 ยังไม่มี Spreadsheet ID

`config.py` บรรทัด 57-67: `DB_ROUTER` มีแค่ กก.1 กับ กก.5 ที่ใส่ ID ไว้ นอกนั้นเป็นสตริงว่าง

```python
"1": {"OPS": "1Sgji6GH..."},   # มี
"5": {"OPS": "1R0x-rH8..."},   # มี
"8": {"OPS": ""},              # ว่าง
```

**ข้อ 3 สั่งให้ Dashboard บก.ทล. แสดงเฉพาะ กก.8 แต่ กก.8 ยังไม่มีฐานข้อมูล**
ผมเขียนโค้ดกรองได้ แต่ทดสอบว่าตัวเลขถูกไม่ได้ และข้อ 1 ที่ให้ ผกก. ดูข้าม กก.
ก็จะเห็นแค่ 2 กก. เหมือนเดิม

ต้องการ: ID ของ กก.8 อย่างน้อยหนึ่งตัว หรือยืนยันว่าให้เขียนโค้ดไว้ก่อนแล้วเทสด้วย กก.5

### 3.2 ข้อมูล PR เก็บที่ไหน

requirement แนะนำ PostgreSQL/SQLite พร้อม 7 ตาราง แต่ระบบทั้งระบบอยู่บน Sheets
และมีเอกสาร `docs/แผนย้ายไปฐานข้อมูลจริง.md` วางแผนย้ายไว้เป็นงานแยกอยู่แล้ว

**ผมแนะนำให้ทำ PR module บน Sheets ก่อน** เพิ่มแท็บใหม่ตามแบบใน `schema.py`
เหตุผล: 7 วันไม่พอทั้งขึ้นฐานข้อมูลใหม่และเขียนฟีเจอร์ และการมีสองแหล่งข้อมูลพร้อมกัน
จะทำให้ debug ยากขึ้นทันที ส่วน audit log ที่จะโตเร็วค่อยย้ายพร้อมกันทั้งระบบในรอบถัดไป

ถ้าคุณอยากเริ่ม Postgres เลย ต้องบวกเวลา 3-4 วันและตัด requirement อื่นออก

### 3.3 อัปโหลดวิดีโอ 1080p ผ่านท่อปัจจุบันไม่ได้

`storage_service.py` บรรทัด 26-27 จำกัด 10 MB ต่อไฟล์ และส่งเป็น base64 ใน JSON
ซึ่งบวมขึ้นอีก 33% วิดีโอ 1080p ความยาว 1 นาทีอยู่ที่ 50-150 MB

ทางเลือก:
- **ก. ภาพอย่างเดียวก่อน** วิดีโอให้แปะลิงก์ Drive/YouTube แทน (ไม่เสียเวลาเพิ่ม)
- **ข. เขียน resumable upload ตรงจากเบราว์เซอร์ไป Drive** (บวก 1 วัน)

ผมแนะนำ ก. ในรอบ 7 วันนี้

### 3.4 FR-03 "เก็บ Post ID / Permalink" หมายถึงโพสต์ขึ้นเพจ Facebook จริงหรือไม่

ถ้าใช่ ต้องมี Facebook App ที่ผ่าน App Review + Page Access Token ซึ่งใช้เวลารออนุมัติ
เป็นสัปดาห์ ไม่จบใน 7 วัน

ผมออกแบบเป็น adapter ไว้ให้ แล้วรอบนี้ทำโหมด manual (เจ้าหน้าที่โพสต์เอง แล้วแปะ URL
กลับเข้าระบบ) ต่อ API จริงทีหลังโดยไม่ต้องรื้อ

### 3.5 คำถามข้อมูลที่ไม่บล็อกโค้ด แต่ต้องมีคนตอบก่อน UAT

- **ข้อ 2**: "หัวหน้าหน่วยงานที่ได้รับการสั่งการ" คือ role ไหนใน `tb_Users` (`Station_Admin`?
  หรือดูจากคอลัมน์ตำแหน่ง) ตอนนี้ `tb_Users` มีคอลัมน์ `เบอร์โทร` อยู่แล้ว ขาดแค่กติกาว่าใครคือหัวหน้า
- **ข้อ 14**: ต้องมีคนจัดกลุ่มข้อหาที่มีอยู่ใน `tb_Charges` เข้า 4 พ.ร.บ. งานนี้เป็นงานข้อมูล
  ไม่ใช่งานโค้ด ผมทำ UI ให้แอดมินกดจัดกลุ่มได้ แต่คนที่รู้กฎหมายต้องเป็นคนตัดสิน
- **ข้อ 6/14**: "ฐานความผิด" ใน Dashboard ปัจจุบันเก็บเป็น JSON string ใน `Charges_Detail`
  ของ `tb_DailyResult` การกรองจะทำได้ระดับ "ข้อหาที่ปรากฏในวันนั้น" ไม่ใช่รายใบจับกุม
  ยกเว้นจะดึงจาก `tb_Arrests` แทน ซึ่งช้ากว่าแต่ละเอียดกว่า ต้องเลือกหนึ่งอย่าง

## 5. แผน 7 วัน

### วันที่ 1 — วางรากฐานที่ทุกข้อใช้ร่วมกัน

ทำของที่ requirement อื่นอีก 8 ข้อต้องเรียกใช้ก่อน จะได้ไม่ต้องแก้ย้อน

1. `useFormDraft(formId)` hook + debounce 500ms + ล้างเมื่อ submit สำเร็จ + หมดอายุ 24 ชม.
   (ข้อ 12) ต่อเข้า `FormShell` ให้ทุกฟอร์มได้ทันทีที่เดียว
2. `LocationPickerModal` component ด้วย react-leaflet (ข้อ 5) พร้อมติดตั้ง
   `leaflet` + `react-leaflet` และ lazy-load ไม่ให้ bundle หน้า login โต
3. `audit_service.py` + แท็บ `tb_AuditLog` (ใช้ทั้งข้อ 9, 10 และ FR-05)
4. แก้ `schema.py` ครบทุกคอลัมน์ที่ต้องเพิ่มในรอบนี้รวดเดียว: พิกัดใน `tb_Checkpoints`,
   slip ใน `tb_FuelOil`, ว.20 ใน `tb_DailyResult`, ว.4 ใน `tb_DailyReport`,
   flag archive ใน `tb_National_Summary` แล้วรัน `test_schema.py` ให้ผ่าน

**ส่งมอบ:** hook + modal + audit log ใช้งานได้ schema เสถียรแล้วไม่ต้องแตะอีก

### วันที่ 2 — EPIC 2 แผนที่ให้จบ

## 8. ข้อจำกัดของโปรเจกต์

รวมทุกเพดานที่ล้อมงานนี้อยู่ เรียงตามผลกระทบต่อ requirement 16 ข้อ

### 8.1 ข้อจำกัดที่แก้ไม่ได้ในรอบนี้

| ข้อจำกัด | หลักฐานในโค้ด | กระทบข้อไหน |
|---|---|---|
| Google Sheets เป็นฐานข้อมูล อ่านได้ 60 ครั้ง/นาที **ต่อทั้งระบบ** | `render.yaml`: องค์กรบล็อกการสร้าง service account key จึงใช้ OAuth บัญชีเดียว | ทุกข้อที่อ่านข้อมูล โดยเฉพาะ 3, 4, 6 |
| ไม่มี transaction และไม่มี row lock | `แผนย้ายไปฐานข้อมูลจริง.md` ข้อ 1 | 10 (แก้ไขรายการ), FR-05 |
| โค้ดอ้างคอลัมน์ด้วย **ตำแหน่ง** ไม่ใช่ชื่อ | `schema.py` บรรทัด 12-13 | ทุกข้อที่เพิ่มคอลัมน์: 7, 8, 11, 15, 16 |
| Render แผนฟรี หลับหลังไม่มีคนใช้ ไม่มีดิสก์ถาวร | `render.yaml:11` `plan: free` | การสาธิต และ FR-02 |

### 8.2 หน้าเว็บต้องเหมือนต้นฉบับ Apps Script

ข้อตกลงเดิมของโปรเจกต์คือ `react_frontend/` ต้องหน้าตาเหมือน `original file/` เป๊ะ
(commit `7a6c2fd` "ยึดเฉพาะฝั่งหน้าเว็บ") ฝั่ง backend แยกทางจาก `รหัส.js` ได้แล้ว
การเพิ่มตารางใหม่จึงไม่ผิดข้อตกลง

**แต่ requirement รอบนี้มีของที่ต้นฉบับไม่มีเลย** ได้แก่ แผนที่ (ข้อ 4, 5, 16),
โมดูล PR เต็มรูปแบบ (ต้นฉบับ `form_pr.html` เป็น stub 1,225 ไบต์ เท่ากับฝั่ง React),
Modal ตรวจก่อนอนุมัติ (ข้อ 9) และหน้าจัดกลุ่มข้อหา (ข้อ 14)

ผมจะยึดภาษาการออกแบบเดิม (`--neon-blue: #00f2ff`, พื้นหลัง dark radial gradient,
ฟอนต์ Kanit, `.glass-card`, Bootstrap 5 + Font Awesome) กับหน้าใหม่ทั้งหมด
ไม่ประดิษฐ์สไตล์ใหม่ **ถ้าคุณอยากได้หน้าตาแบบอื่นสำหรับของใหม่ ต้องบอกก่อนวันที่ 1**
เพราะแก้ทีหลังคือรื้อ

เรื่อง react-router: การไม่มี router แปลว่าปุ่มย้อนกลับของเบราว์เซอร์พาออกจากแอปเลย
ไม่ใช่กลับหน้าก่อนหน้า ข้อ 12 ที่ขอ "กดย้อนกลับแล้วข้อมูลไม่หาย" จึงครอบคลุมเฉพาะปุ่ม
ย้อนกลับในแอป ถ้าต้องการให้ปุ่มเบราว์เซอร์ทำงานด้วย ต้องใส่ router ซึ่งกระทบ `App.tsx`
ทั้งไฟล์และทุก dashboard ที่รับ prop `onBack` บวก 1 วัน

### 8.3 ข้อจำกัดด้านคนและเวลา

- นักพัฒนา 1 คน 7 วัน ไม่มีคนทำ QA แยก การทดสอบกินเวลาในวันเดียวกัน

## 9. ความเสี่ยงที่ต้องเฝ้า

**โควตา Google Sheets** เอกสาร `docs/แผนย้ายไปฐานข้อมูลจริง.md` ระบุว่าเคยเจอ 429
ตอนออกรายงานแล้ว การเพิ่มโมดูล PR อีก 3 ตารางกับ audit log ที่เขียนทุก action
จะดันโควตาขึ้นอีก ถ้าเจอ 429 ระหว่างพัฒนา ให้เขียน audit log แบบ batch ท้าย request
แทนการเขียนทันที

**`tb_National_Summary` เคยเต็ม 1,023 แถวจนข้อมูลหาย 6 กก. แบบเงียบ** ข้อ 3 ที่ให้เก็บ
กก.1-7 ไว้เป็น archive จะทำให้แถวโตเร็วขึ้น ต้องเช็คเพดานแถวก่อนเริ่มวันที่ 3

**การแก้ `schema.py` ทำให้ข้อมูลเก่าลงผิดช่อง** ถ้าเพิ่มคอลัมน์กลางตาราง โค้ดอ้างคอลัมน์
ด้วยตำแหน่ง ไม่ใช่ชื่อ เพราะแบบนี้แผนวันที่ 1 จึงกำหนดให้เพิ่มคอลัมน์ **ต่อท้ายเท่านั้น**
และรัน `test_schema.py` ทุกครั้ง

**Render free tier พัก** คนแรกของวันรอ 30-50 วินาที ถ้าจะสาธิตให้ผู้บังคับบัญชาดู
ต้องยิงปลุกก่อนล่วงหน้า
